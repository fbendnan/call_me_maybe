# Call Me Maybe

## Description

**Call Me Maybe** is a Python project that implements **JSON-constrained decoding** for Large Language Models (LLMs). The goal is to generate valid function calls by restricting the model's output so that it always conforms to a predefined JSON schema.

Instead of allowing the model to generate arbitrary text, the decoder only permits tokens that are valid according to the expected JSON structure and data types. This significantly improves the reliability of structured outputs and prevents malformed JSON.

The project reads a list of function definitions and a set of prompts, then generates valid function calls matching the provided schema.

---

## Features

* JSON-constrained decoding
* Support for multiple function definitions
* Pydantic validation of input files
* Automatic generation of valid JSON
* Support for the following parameter types:

  * `string`
  * `number`
  * `integer`
  * `boolean`
* Detection of invalid schemas before generation

## Algorithm Explanation

The constrained decoding algorithm generates JSON incrementally while enforcing the expected schema.

The generation process follows these steps:

1. Validate the input schema using Pydantic.
2. Select the function that best matches the prompt.
3. Generate the JSON object token by token.
4. Restrict the valid tokens according to the current JSON context.
5. Generate parameter values according to their declared type:

   * **String:** generate characters until the closing quotation mark is produced.
   * **Number:** only numeric tokens, decimal point, and optional sign are permitted.
   * **Integer:** only integer digits and an optional leading sign are allowed.
   * **Boolean:** only `true` or `false` can be generated.
6. Continue recursively until the complete JSON object has been produced.

Because invalid tokens are never selected, the generated output always respects the expected structure.

---

## Design Decisions

Several implementation choices were made to improve reliability and maintainability:

* **Pydantic** is used to validate all input files before generation begins.
* Each JSON type is generated by a dedicated decoding function, making the implementation modular.
* JSON objects are built recursively, allowing nested structures to be supported in the future.
* Type-specific generation functions simplify extending the decoder with additional JSON types.

---

## Performance Analysis

### Accuracy

The constrained decoder guarantees that the generated JSON respects the expected schema, eliminating malformed outputs caused by unconstrained generation.

### Speed

Constraining the token selection introduces a small computational overhead compared with unrestricted decoding. However, the search space is significantly reduced, which can compensate for part of this cost.

### Reliability

Schema validation before generation and token-level constraints during decoding make the implementation robust against invalid JSON generation.

---

## Challenges Faced

Several challenges were encountered during development:

* Designing recursive generation for nested JSON objects.
* Handling different primitive JSON types independently.
* Preventing invalid JSON syntax during generation.
* Validating user-provided schemas before decoding.
* Managing tokenizer behavior for multi-token values.

These issues were addressed by separating the generation logic into dedicated functions and validating all inputs with Pydantic.
